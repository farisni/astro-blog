# 🧠 先建立一个 CPU 心智模型

一个典型 CPU 可以先粗略看成四类部件：

| 部件 | 作用 | 类比 Java |
|---|---|---|
| 运算器 | 做加法、减法等信息处理 | 执行 `+`、`-` 等运算的部分 |
| 控制器 | 决定下一步做什么 | 解释并调度指令的部分 |
| 寄存器 | 保存 CPU 当前正在使用的数据 | CPU 内部的一组高速变量 |
| 内部总线 | 在部件之间传送数据 | 部件之间的数据通道 |

对汇编程序员来说，寄存器最重要。程序员不能直接用 Java 风格的变量名控制 CPU，而是通过指令读写寄存器：

```text
执行指令 -> 改变寄存器内容 -> 影响 CPU 后续行为
```

8086 一共有 14 个寄存器：

```text
AX BX CX DX SI DI SP BP IP CS SS DS ES PSW
```

本教程只重点使用 AX、BX、CX、DX、CS 和 IP；其余寄存器会在后续课程中逐步学习。

> [!NOTE]
> 学习汇编时，寄存器不是抽象的变量名，而是 CPU 内部容量固定的存储位置。理解每条指令时，先确认它读写了哪个寄存器。

# 🧰 通用寄存器：AX、BX、CX、DX

8086 的寄存器都是 16 位，可以保存两个字节。AX、BX、CX、DX 通常用来保存一般数据，因此称为通用寄存器。

### 16 位寄存器和两个 8 位寄存器

AX 可以拆成两个可以独立使用的 8 位寄存器：`AX = AH(高 8 位) + AL(低 8 位)`。

同样：

```text
BX = BH + BL
CX = CH + CL
DX = DH + DL
```

可以用 Java 的类比帮助理解：AX 类似一个 16 位容器，AH 和 AL 是这个容器的高半部分和低半部分。但它们不是 Java 中真正的三个独立变量：修改 AH 或 AL，会改变 AX 的整体二进制内容。

例如，若 `AX = 4E20H`，那么：

> [!columns-1-1]
> > [!plain]
> > `AH = 4EH`
>
> > [!plain]
> > `AL = 20H`

原书图 2.3 和图 2.4 展示了这种对应关系：

> [!TIP]
> 可以把 AX 暂时类比成一个 `short`，把 AH 和 AL 类比成它的高 8 位和低 8 位。但 AH、AL 的修改会直接影响 AX 的二进制内容，不要把它们当成三个互不相关的 Java 变量。

![16 位寄存器拆分为两个 8 位寄存器](images/143069fdcd4f583eb8ac8c506563b206834f29d908a02159acdb127a0118c8cb.jpg)

### 一个寄存器能保存多大的数

无符号数的最大值由位数决定：

```text
8 位最大值  = 2^8  - 1 = 255  = FFH
16 位最大值 = 2^16 - 1 = 65535 = FFFFH
```

因此：

- 8 位寄存器不能保存 `100H` 这样的 9 位二进制范围数值；
- 16 位寄存器可以保存最多 4 位十六进制数；
- 计算结果超过寄存器容量时，低位仍保留，高位进位不能放进该寄存器。

> [!WARNING]
> 判断一条指令是否合法时，先检查数值能否放入目标寄存器：8 位最多 `FFH`，16 位最多 `FFFFH`。

# 🔢 字节、字和数制

### byte 和 word

8086 主要处理两种尺寸的数据：

| 名称 | 大小 | 常见存放位置 |
|---|---:|---|
| byte（字节） | 8 bit | 8 位寄存器，或一个内存单元 |
| word（字） | 16 bit | 16 位寄存器，或两个连续内存单元 |

一个 word 由高位字节和低位字节组成。比如：

```text
20000 = 4E20H
高位字节 = 4EH
低位字节 = 20H
```

在 AX 中，`AH` 保存高位字节，`AL` 保存低位字节。

### 二进制、十进制和十六进制

计算机内部使用二进制，但十六进制更容易观察字节边界。一个十六进制数字正好对应四个二进制位：

```text
0100 1110 0010 0000B
  4    E    2    0H
```

本教程采用以下后缀区分进制：

```text
十进制：20000
十六进制：4E20H
二进制：0100111000100000B
```

看到 `4E20H` 时，可以立即拆出两个字节 `4EH` 和 `20H`。这也是汇编学习中经常使用十六进制的原因。

# ☕ 用 Java 类比读懂 mov 和 add

汇编指令通常写成：

```text
指令  目的操作数, 源操作数
```

### mov：把源操作数的值复制到目的操作数

> [!columns-1-1]
> > [!plain]
> > ```asm
> > mov ax,18
> > ```
>
> > [!plain]
> > ```java
> > ax = 18;
> > ```

可以先把两者看成同一个“把值写入目标”的动作。

但 `mov` 不会清空源操作数。例如：

> [!columns-1-1]
> > [!plain]
> > ```asm
> > mov ax,bx
> > ```
>
> > [!plain]
> > ```text
> > AX = BX
> > ```

执行后 BX 仍然保持原值。

> [!NOTE]
> `mov` 的“传送”更接近 Java 的赋值：它把源操作数的值复制到目的操作数，不会把源操作数清空。

### add：把结果写回第一个操作数

> [!columns-1-2]
> > [!plain]
> > ```asm
> > add ax,8
> > ```
> >
> > ```asm
> > add ax,bx
> > ```
>
> > [!plain]
> > ```java
> > ax = ax + 8;
> > ax = ax + bx;
> > ```

两条 `add` 指令都把结果写回第一个操作数，第二个操作数不会被修改。

### 典型执行过程

初始：

```text
AX = 0000H
BX = 0000H
```

执行：

```asm
mov ax,4E20H
add ax,1406H
mov bx,2000H
add ax,bx
mov bx,ax
```

结果依次为：

| 指令 | AX | BX |
|---|---:|---:|
| `mov ax,4E20H` | `4E20H` | `0000H` |
| `add ax,1406H` | `6226H` | `0000H` |
| `mov bx,2000H` | `6226H` | `2000H` |
| `add ax,bx` | `8226H` | `2000H` |
| `mov bx,ax` | `8226H` | `8226H` |

如果再执行 `add ax,bx`，计算结果是 `1044CH`，但 AX 只有 16 位，最终 AX 只能保留 `044CH`。

最高位的 `1` 是进位，当前阶段先理解为“无法保存在 AX 中”。后续学习标志寄存器时再讨论如何观察进位。

### 操作数位数必须一致

下面的指令是合法的：

```asm
mov ax,bx
mov bx,cx
mov ax,18H
mov al,18H
add ax,bx
add ax,20000
```

下面的指令有问题：

```asm
mov ax,bl       ; 16 位和 8 位不能直接传送
mov bh,ax       ; 8 位和 16 位不能直接传送
mov al,20000    ; 20000 超出 8 位寄存器范围
add al,100H     ; 100H 超出 8 位操作数范围
```

判断指令时，先问两个问题：

1. 目的操作数是 8 位还是 16 位？
2. 源操作数的位数和值是否匹配？

> [!WARNING]
> `AX` 是 16 位，`AL` 和 `BL` 是 8 位，不能直接把它们混用在同一条数据传送或运算指令中。

### 8 位运算不会自动变成 16 位运算

假设 `AX = 00C5H`，执行 `add al,93H`。这里进行的是 8 位运算：

> [!columns-1-2]
> > [!plain]
> > `C5H + 93H = 158H`
>
> > [!plain]
> > AL 只能保留低 8 位，因此 AX 变成 `0058H`。

CPU 不会因为 AL 溢出，就把进位自动写进 AH。只有明确使用 AX 做 16 位运算时，AH 才属于这个 16 位结果的一部分。

> [!WARNING]
> `add al,93H` 是 8 位运算，不能把它理解成“先算 AX，再把结果拆回 AH 和 AL”。只有 `add ax,...` 才会把整个 AX 当作一个 16 位操作数。

# 🧭 物理地址：8086 如何访问 1MB 内存

### 物理地址是什么

内存可以看成一维的连续空间，每个内存单元都有唯一编号。这个编号就是物理地址。

8086 有 20 根地址总线，因此可以表示 20 位地址：`2^20 = 1MB`。

但 8086 是 16 位结构，内部一次只能处理 16 位数据和地址。如果只直接使用一个 16 位地址，最多只能访问 64KB。为了解决这个矛盾，8086 使用两个 16 位数合成一个 20 位物理地址。

### 段地址和偏移地址

公式是 `物理地址 = 段地址 × 16 + 偏移地址`。

例如：

```text
段地址   = 1000H
偏移地址 = 0020H

物理地址 = 1000H × 16 + 0020H
         = 10000H + 0020H
         = 10020H
```

在 8086 中，`1000:0020` 就是对这个地址的段地址:偏移地址表示。

> [!NOTE]
> 段地址和偏移地址是两部分输入，物理地址才是最终定位到的内存单元。计算时先把段地址左移 4 位（等价于乘以 16），再加上偏移地址。

### 为什么乘以 16 等于左移 4 位

十六进制每一位对应四个二进制位。因此，二进制左移 4 位，也就是十六进制左移 1 位：

```text
2H << 1 = 4H
2H << 4 = 20H
```

所以地址加法器可以把段地址左移 4 位，再加上偏移地址。

### 一个物理地址可以有多个表示

同一个物理地址不一定只有一种段地址:偏移地址表示。例如：

```text
2000H × 16 + 1F60H = 21F60H
2100H × 16 + 0F60H = 21F60H
21F0H × 16 + 0060H = 21F60H
21F6H × 16 + 0000H = 21F60H
```

这说明“段”不是内存天然切好的固定区域，而是程序员根据需要对连续内存的一种组织方式。

> [!WARNING]
> 不要把“段”理解成硬件提前划好的内存分区。8086 提供的是一种寻址方式，程序员可以根据需要把一段连续地址看作代码段、数据段或其他用途的段。

### 段的两个限制

由于段地址乘以 16 后一定是 16 的倍数：

- 一个段的起始物理地址一定是 16 的倍数；
- 偏移地址是 16 位，所以一个段最多覆盖 64KB。

# ⚙️ CS、IP：CPU 下一步执行什么

### CS 和 IP 的职责

8086 有多个段寄存器，其中：

- CS 保存代码段地址；
- IP 保存当前指令的偏移地址。

任意时刻，CPU 都把 `CS:IP` 指向的内存内容当作指令。

![8086 CPU 读取和执行指令的相关部件](images/e5a8f9361d05587dffc2e119a5cb63fb61074569e9021f502c07a467697087c7.jpg)

### 取指、增加 IP、执行

CPU 执行指令可以抽象成一个循环：

```text
1. 根据 CS:IP 计算指令的物理地址
2. 从内存读取机器码
3. IP 增加当前指令的长度
4. 执行这条指令
5. 回到第 1 步
```

例如：

```text
CS = 2000H
IP = 0000H
物理地址 = 20000H
```

如果 `20000H` 处的机器码是，右侧就是它对应的汇编指令：

> [!columns-1-1]
> > [!plain]
> > ```text
> > B8 23 01
> > ```
>
> > [!plain]
> > ```asm
> > mov ax,0123H
> > ```

这条指令长度为 3 字节，所以取指后 `IP = 0000H + 3 = 0003H`。

之后 CPU 会从 `2000:0003` 继续读取下一条指令。

> [!TIP]
> 读指令执行过程时，可以像调试 Java 程序一样维护一个状态表：每执行一条指令，就记录 AX、BX、CS、IP 的新值。区别在于，IP 的变化量取决于机器指令的字节长度。

### 指令长度决定 IP 增加多少

下面的机器码长度不同：

| 地址 | 机器码 | 汇编指令 | 长度 |
|---|---|---|---:|
| `20000H–20002H` | `B8 23 01` | `mov ax,0123H` | 3 字节 |
| `20003H–20005H` | `BB 03 00` | `mov bx,0003H` | 3 字节 |
| `20006H–20007H` | `89 D8` | `mov ax,bx` | 2 字节 |
| `20008H–20009H` | `01 D8` | `add ax,bx` | 2 字节 |

因此，IP 不是每次固定加 1，而是增加“刚刚读取的指令长度”。

### CPU 如何区分数据和指令

内存中的二进制本身没有“这是数据”或“这是指令”的标签。

同一段二进制信息：

- 由 `CS:IP` 指向时，CPU 按指令解释；
- 被普通数据指令访问时，可以按数据解释。

所以，是否为指令，关键不在内存单元本身，而在 CPU 是否把它作为 `CS:IP` 指向的内容读取和执行。

> [!NOTE]
> “代码”和“数据”在内存中都只是二进制。解释方式由使用它们的指令和当前的 `CS:IP` 决定。

# 🔀 用 jmp 改变执行位置

### 同时修改 CS 和 IP

> [!columns-1-2]
> > [!plain]
> > ```asm
> > jmp 2AE3:0003
> > ```
>
> > [!plain]
> > 执行后：
> >
> > ```text
> > CS = 2AE3H
> > IP = 0003H
> > ```
> >
> > 下一条指令的物理地址：
> > `2AE3H × 16 + 0003H = 2AE33H`

### 只修改 IP

> [!columns-1-2]
> > [!plain]
> > ```asm
> > jmp ax
> > ```
>
> > [!plain]
> > 执行前：
> >
> > ```text
> > AX = 1000H
> > CS = 2000H
> > IP = 0003H
> > ```
> >
> > 执行后：
> >
> > ```text
> > AX = 1000H
> > CS = 2000H
> > IP = 1000H
> > ```

可以把它理解为 `IP = AX`。

但这只是帮助理解的“汇编解释汇编”，并不代表存在一条真正的 `mov IP,ax` 指令。8086 不允许用普通 `mov` 直接修改 IP，改变执行位置要使用转移指令。

# 🧱 代码段是什么

假设从物理地址 `123B0H` 开始存放 10 个字节的指令：

```asm
mov ax,0000
add ax,0123H
mov bx,ax
jmp bx
```

可以把 `123B0H–123B9H` 这一段连续内存定义为代码段：

```text
代码段地址 = 123BH
代码段偏移 = 0000H
```

但“定义为代码段”只是程序员的安排。CPU 不会自动执行它。要让 CPU 从第一条指令开始执行，必须让：

```text
CS = 123BH
IP = 0000H
```

也就是让 `CS:IP` 指向代码段的首地址。

# 🐞 Debug：把抽象过程变成可观察过程

> [!WARNING]
> 本节是 How-to 内容。原书介绍的是 DOS/Windows 时代的 Debug 工具；现代系统通常不能直接按原书环境运行它。本节重点是理解命令分别观察 CPU 的哪一部分。

### 六个核心命令

| 命令 | 用途 | 观察对象 |
|---|---|---|
| `R` | 查看或修改寄存器 | AX、BX、CS、IP 等 |
| `D` | 查看内存 | 内存中的字节和 ASCII |
| `E` | 修改内存 | 数据、字符或机器码 |
| `U` | 反汇编 | 机器码对应的汇编指令 |
| `T` | 单步执行 | `CS:IP` 指向的指令及寄存器变化 |
| `A` | 写入汇编指令 | 由 Debug 翻译并写入机器码 |

### R：查看和修改寄存器

直接输入 `R` 可以查看寄存器。重点观察 `CS:IP`，它表示 CPU 当前准备读取的指令位置。

修改 AX：输入 `R AX`。

然后输入新的十六进制值。

### D：查看内存

查看 `10000H`，可以使用 `D 1000:0`，因为 `1000H × 16 + 0000H = 10000H`。

指定查看范围：

`D 1000:0 9`

这表示查看 `1000:0` 到 `1000:9` 的内容。Debug 通常同时显示：

1. 内存地址；
2. 十六进制字节；
3. 对应的 ASCII 字符。

### E：修改内存

一次写入多个字节：`E 1000:0 01 02 03 04`

这会从 `1000:0` 开始依次写入四个字节。

也可以使用交互式方式：`E 1000:10`

输入数据后按空格处理当前单元；不输入数据直接按空格，可以保留原值；按 Enter 结束。

E 命令写入的可以是：

- 数值；
- 字符；
- 字符串；
- 机器码。

内存并不区分这些内容，区别来自后续如何解释它们。

### U：把机器码翻译成汇编

如果从 `1000:0` 写入 `E 1000:0 B8 01 00 B9 02 00 01 C8`，可以使用 `U 1000:0`。

查看机器码对应的指令，例如：

```asm
mov ax,1
mov cx,2
add ax,cx
```

这里可以观察到：同一段内存先被 D 命令当作数据查看，又被 U 命令当作机器指令解释。

> [!NOTE]
> `D` 和 `U` 并没有改变内存内容，它们只是采用了不同的解释方式：D 按字节显示，U 按机器指令边界反汇编。

### T：单步执行

T 命令（输入 `T`）执行 `CS:IP` 当前指向的指令：

实验前要先用 R 命令把 `CS:IP` 调整到机器码所在的位置。执行后重点观察：

- AX、BX 等寄存器是否改变；
- IP 增加了多少；
- 下一条 `CS:IP` 指向哪里。

例如执行 `mov ax,0001` 后，AX 变成 `0001H`，IP 增加 3，因为该指令占 3 个字节。

> [!TIP]
> 用 T 单步时，先看执行前的 `CS:IP`，再看执行后的寄存器变化。这样可以把“取指位置”和“指令产生的效果”分开理解。

### A：直接写入汇编指令

相比用 E 命令手动输入机器码，A 命令更接近写汇编程序：输入 `A 1000:0`。

随后输入：

```asm
mov ax,1
mov cx,2
add ax,cx
```

Debug 会将这些汇编指令翻译成机器码写入内存。输入空行结束。

# 🧪 动手练习：跟踪一段指令

可以用下面的思路分析一段指令，不必一开始就依赖工具。

```asm
mov ax,001AH
mov bx,0026H
add al,bl
add ah,bl
add bh,al
mov ah,0
add al,85H
```

建议每执行一条指令就记录：

| 步骤 | 指令 | AX | BX | 说明 |
|---:|---|---|---|---|
| 1 | `mov ax,001AH` | `001AH` | — | AX 整体被赋值 |
| 2 | `mov bx,0026H` | `001AH` | `0026H` | BX 整体被赋值 |
| 3 | `add al,bl` | 只改变 AL | `0026H` | 8 位运算 |
| 4 | `add ah,bl` | 只改变 AH | `0026H` | 仍然是 8 位运算 |
| 5 | `add bh,al` | 不变 | 只改变 BH | 只影响 BX 的高 8 位 |

每一步都先确定“操作数的位数”，再更新对应寄存器部分。

# 💾 内存中字的存储

本页范围已经进入第 3 章，开始讨论寄存器与内存之间的关系。

内存的基本存储单元是一个字节，而一个 word 有 16 位、两个字节。因此，一个 word 需要占用两个连续的内存单元。

8086 将 word 的低位字节放在低地址，高位字节放在高地址。例如：

```text
4E20H
低位字节 = 20H
高位字节 = 4EH
```

从地址 0 开始存放时：

| 内存地址 | 内容 |
|---:|---:|
| 0 | `20H` |
| 1 | `4EH` |

地址 0 和地址 1 合起来可以看作“0 地址字单元”。这里的“0 地址”指起始地址，不是说它只占一个字节。

> [!NOTE]
> “低地址放低位字节”是理解 8086 内存数据的关键。读取一个 word 时，需要把低地址中的字节看作低 8 位，把高地址中的字节看作高 8 位，再组合成 16 位数。

# 📚 本教程的核心复习表

### 寄存器

| 寄存器 | 本教程中的作用 |
|---|---|
| AX、BX、CX、DX | 通用数据寄存器 |
| AH、AL | AX 的高 8 位和低 8 位 |
| CS | 当前代码段地址 |
| IP | 当前指令的偏移地址 |
| CS:IP | CPU 当前要读取的指令位置 |

### 地址

| 关系 | 表达式 |
|---|---|
| 物理地址 | `段地址 × 16 + 偏移地址` |
| 段地址换算 | `段地址 × 16 = 段地址左移 4 位` |

### 指令

| 指令 | 直观含义 |
|---|---|
| `mov ax,bx` | `AX = BX` |
| `add ax,bx` | `AX = AX + BX` |
| `jmp ax` | `IP = AX` |
| `jmp 2000:0003` | `CS = 2000H`，`IP = 0003H` |

### 读汇编示例的固定步骤

看到一条指令时，按以下顺序分析：

1. 目的操作数是谁？
2. 源操作数是谁？
3. 两个操作数分别是 8 位还是 16 位？
4. 执行后哪些寄存器部分会改变？
5. 如果是跳转指令，CS 或 IP 会变成什么？
6. 如果涉及内存，使用段地址和偏移地址算出物理地址。
